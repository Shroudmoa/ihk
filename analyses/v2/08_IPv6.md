# 8. IPv6

*Quelle: GA2 Aufgabe 3 (2024 Sommer)*

> ✅ **Verifiziert am echten Prüfungskorpus:** IPv6 ist **seit 2022 in
> fast jedem Jahrgang** Prüfungsthema:
> - **2022S:** Präfix `2001:db8:ca::/56` → maximale Anzahl Subnetze bei
>   **SLAAC** (Rest muss `/64` bleiben, damit die Interface-ID Platz hat)
>   = 8 Bit frei = **256 Subnetze**
> - **2022W:** IPv6-Ping-Trace, AAAA-Antwort auswerten, **Hop-Berechnung**
>   über TTL-Differenz (128 − 118 = **10 Hops**), **DNS-Load-Balancing**
>   als Erklärung, warum ein Name mehrere IP-Antworten liefert
> - **2024S:** `2001:DB8:CAFE::/48` → 4 gleich große Subnetze (`/50`,
>   siehe 8.3); **SLAAC** (Link-Local + Router Advertisement) + 3 Gründe,
>   warum trotzdem **DHCPv6** nötig ist (Zeitserver/Druckserver/TFTP/
>   Protokollierung)
> - **2024W:** `2001:db8:1234::/56` → **identische** SLAAC-Aufgabe wie
>   2022S (256 Subnetze)
> - **2025S:** `2001:db8:9876::/56` → `/64`-Subnetze (256 Stück); 1.,
>   2., vorletztes und letztes Subnetz konkret benennen
> - **2026S:** **Dual-Stack**-Betrieb, bewusste Entscheidung für
>   **DHCPv6 statt SLAAC** (zentrale Verwaltung als Grund); IPv6 im
>   Wireshark-Trace erkennen (link-local `fdbf:...`, global `2003:...`)

## 8.1 Warum IPv6?

- IPv4: 32 Bit → Adressen knapp (Erschöpfung)
- IPv6: **128 Bit** → praktisch unbegrenzt
- Kein NAT mehr nötig, IPsec eingebaut, SLAAC, effizienteres Routing

## 8.2 Vorteile von IPv6 (nenne 3)

- Größerer Adressraum (Skalierbarkeit)
- Eingebaute Sicherheit (IPsec auf Netzwerkschicht)
- Kein NAT nötig
- Zustandslose Autokonfiguration (SLAAC)
- Bessere Header-Struktur (weniger Aufwand)
- QoS (Verzögerungsempfindliche Pakete)

## 8.3 Subnetze bilden (Rechnen!)

Gegeben: `2001:DB8:CAFE::/48`, daraus **4 gleich große** Subnetze.

/48 → 16 Bit für Subnetze verfügbar. 4 Subnetze = 2 Bit → **/50**.

| Nr. | Netz-Adresse | 2. Hex-Ziffer (Wert) |
|----|--------------|----------------------|
| 1 | `2001:DB8:CAFE::/50` | 0000 |
| 2 | `2001:DB8:CAFE:4000::/50` | 0100 → 0x4000 |
| 3 | `2001:DB8:CAFE:8000::/50` | 1000 → 0x8000 |
| 4 | `2001:DB8:CAFE:C000::/50` | 1100 → 0xC000 |

**Merkregel:** 4 Teile → 2. Hex-Gruppe aufteilen in 0000 / 4000 / 8000 /
C000.

## 8.3b Subnetze bei SLAAC: `/56` → `/64` (2022S, 2024W, 2025S)

Häufigere Variante als 8.3: Gegeben ein **/56**-Präfix, z. B.
`2001:db8:ca::/56` (2022S) oder `2001:db8:1234::/56` (2024W) bzw.
`2001:db8:9876::/56` (2025S).

**Regel:** Bei SLAAC muss jedes Subnetz **mindestens /64** bleiben (die
Interface-ID braucht 64 Bit). Von `/56` bis `/64` sind das **8 Bit** frei
→ **2^8 = 256 mögliche Subnetze**.

| Subnetz | Beispiel-Adresse (2025S: `2001:db8:9876::/56`) |
|---------|--------------------------------------------------|
| 1. Subnetz | `2001:db8:9876:00::/64` |
| 2. Subnetz | `2001:db8:9876:01::/64` |
| vorletztes (255.) | `2001:db8:9876:fe::/64` |
| letztes (256.) | `2001:db8:9876:ff::/64` |

→ Die letzten beiden Hex-Ziffern der 4. Hex-Gruppe zählen einfach von
`00` bis `FF` hoch (0–255 = 256 Subnetze).

## 8.3c Hop-Berechnung & DNS-Load-Balancing (2022W)

- **Hop-Anzahl aus TTL-Differenz:** Startet ein Betriebssystem mit
  TTL = 128 und die Antwort kommt mit TTL = 118 an, wurden unterwegs
  **128 − 118 = 10 Hops** durchlaufen (jeder Router dekrementiert TTL
  um 1).
- **DNS-Load-Balancing:** Liefert `nslookup`/`ping` für denselben
  Hostnamen **mehrere unterschiedliche IP-Adressen**, verteilt der
  DNS-Server die Last bewusst auf mehrere Server (Round-Robin-DNS) –
  kein Fehler, sondern gewolltes Load-Balancing.

## 8.4 SLAAC (Stateless Address Autoconfiguration)

Client erzeugt selbst eine **link-local** Adresse, bekommt per
**Router Advertisement** den globalen Präfix + DNS-Server. Gateway =
Absender des Router Advertisements. Kein DHCP zwingend nötig.

## 8.5 Warum trotzdem DHCPv6?

- Adresspools verwalten & protokollieren
- Zusatzdaten vergeben: DNS-, Zeitserver, Druckserver, TFTP
- Adressvergabe über mehrere Subnetze zentral steuern

## Typische Prüfungsaufgabe

> „Bilden Sie aus 2001:DB8:CAFE::/48 vier gleich große Subnetze."

→ Präfix um 2 Bit verlängern (/50), 2. Hex-Gruppe wie oben staffeln.
Rechenweg (binär) mit angeben!
